# BRAND

Status: v1, made in step 1b. All files are generated by `assets/brand/build.py` from one set of constants, so the mark can be changed in one place.

## Concept

**A check mark built from stacked backups.** To vouch is to give a trusted guarantee. BackupVouch keeps several backup generations, but only one claim matters: the newest one has been restored and checked. The mark shows three identical check shapes stacked like layers, offset downward. Only the front layer, the one that has been proven, is in the accent colour. The layers behind are the stored backups, quiet and neutral.

Why this and not the alternatives: a notary seal says "official" but not "restored", and a stamp that completes on success is hard to read at 16 pixels. The stacked check carries both ideas (a backup history, and a verdict on the newest entry) in one shape that survives small sizes. It avoids the clichés on the project's list: no shield, padlock, cloud, cylinder, letter in a container, gradient, glow or 3D effect. The mark uses three colours, and the mono version uses one.

## Palette

| Name | Hex | Role |
|---|---|---|
| Ledger Ink | `#14212E` | text, wordmark on light, background of the social card and the dark theme |
| Vouch Teal | `#0E7C73` | the front (verified) layer on light backgrounds |
| Vouch Teal Bright | `#35C2B5` | the front layer on dark backgrounds |
| Archive Slate | `#6B7F95` | the middle layer on light backgrounds |
| Archive Mist | `#C9D3DE` | the back layer on light backgrounds |
| Paper | `#F5F7FA` | light background |

On dark backgrounds the layers become `#E8EEF4` (text), `#35C2B5`, `#5B6E83` and `#34465A`. Measured contrast (WCAG): Ledger Ink on Paper 15.2:1, Vouch Teal on Paper 4.7:1, Vouch Teal Bright on Ledger Ink 7.4:1. The Slate and Mist layers are decorative (1.4 to 3.8:1) and must never carry text. Status colours for a future dashboard (failed, warning) are not part of the mark and are defined in step 8; the brand must not contradict them, and failure must never rely on colour alone.

## Typeface

The wordmark is IBM Plex Sans, "Backup" in Regular (400) and "Vouch" in SemiBold (600), SIL Open Font License 1.1, taken from the npm package `@fontsource/ibm-plex-sans`. It is an engineered grotesque with a technical, calm character that suits DevOps tooling and is not one of the usual startup typefaces. The weight change puts the emphasis on the promise (vouch) without a second colour. The text is converted to outlines, so the SVGs need no installed font. If a dashboard is built (step 8) it may use IBM Plex Sans (self-hosted woff2) for text and IBM Plex Mono for logs and keys.

## Construction

- Grid: 64 by 64 units. The check is one polyline `(8,23) (21,36) (56,9)`, stroke width 6, mitred joins, butt caps (hard, precise edges, no rounding).
- Layers: three copies offset by 9 units vertically, which leaves a 3-unit gap between layers (measured vertically). Back layer first, front layer last.
- Favicon: two layers only, stroke width 12, offset 15, so it stays readable at 16 pixels.
- Lockup: mark, a gap of 16 units, then the wordmark at 44 units, vertically centred on the mark.
- Minimum size: mark 16 px, lockup 120 px wide. Below 32 px use `favicon.svg`.
- Clear space: at least half the mark's width (32 units) on every side.

## Files

| File | Use |
|---|---|
| `logo-mark.svg`, `logo-mark-dark.svg` | mark alone, for light and dark backgrounds |
| `logo.svg`, `logo-dark.svg` | horizontal lockup, for light and dark backgrounds |
| `logo-mono.svg` | single colour (Ledger Ink) for print and one-colour contexts |
| `favicon.svg`, `favicon.ico`, `favicon-32.png`, `apple-touch-icon.png` | favicons |
| `social-preview.svg`, `social-preview.png` | GitHub social preview, 1280 by 640 |

Dark backgrounds are handled with separate `-dark` files everywhere, not with `prefers-color-scheme` inside the SVG, because GitHub and many viewers ignore it for images. `favicon.svg` uses mid-tone colours that work on both light and dark browser tabs.

## Using it

README (already wired):

```html
<picture>
  <source media="(prefers-color-scheme: dark)" srcset="assets/brand/logo-dark.svg">
  <img alt="BackupVouch" src="assets/brand/logo.svg" width="320">
</picture>
```

Favicon links for any page, including the optional dashboard (step 8):

```html
<link rel="icon" href="/favicon.svg" type="image/svg+xml">
<link rel="icon" href="/favicon.ico" sizes="48x48">
<link rel="apple-touch-icon" href="/apple-touch-icon.png">
```

The dashboard embeds `favicon.svg` and `favicon.ico` with `go:embed`, uses `logo-mark.svg` (and `logo-mark-dark.svg`) in the header, and derives its colour tokens from the palette above (Ledger Ink for text, Paper for the page, Vouch Teal only for "verified").

## Do and don't

- Do keep the front layer teal and the others neutral. The accent means "proven".
- Do use `logo-dark.svg` on dark backgrounds, never the light logo on dark.
- Don't recolour the front layer red or amber. A failure is shown with status text and icons, not by changing the logo.
- Don't rotate, outline, add shadows, gradients or glow, or put the mark in a circle or square.
- Don't change the layer offset, add layers, or round the corners.
- Don't set the wordmark in another font or re-space it.

## Regenerating

    npm i @fontsource/ibm-plex-sans
    pip install fonttools cairosvg pillow
    python3 assets/brand/build.py node_modules/@fontsource/ibm-plex-sans/files

The rasters were rendered with cairosvg and checked at 16, 32, 64 and 256 pixels on light and dark backgrounds. Look at `favicon-32.png` and `favicon.ico` in a real browser tab once; tab rendering differs between browsers.
